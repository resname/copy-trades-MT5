# Broker/Server Browser — Design Spec

## Goal

Let the user pick an MT5 server by **broker name** (which they remember)
instead of typing an exact server string (which they don't). Today the
`Server` field is free-text in both the master form and the slave editor,
passed straight to `mt5.initialize(server=…)`. This adds a browsable,
searchable **Broker → Server** picker backed by a merged broker catalog.

## Background & constraints

- The MetaTrader5 Python package exposes **no** server-listing function
  (only symbols). Confirmed via `dir(MetaTrader5)`.
- There is **no public MetaQuotes endpoint** for broker/server discovery —
  MetaQuotes' broker registry is internal to the terminal (not REST).
- The realistic free, no-auth live source is the **TradeVPS community
  broker-servers API**: `GET https://broker-servers.apis.tradevps.net/` →
  `200 application/json`, no auth. Crowd-sourced (~35 brokers), not official.
  Response shape:
  `{"brokers":[{"id","name","website","servers":[{"name","type":"demo|real"}]}]}`
- Global constraints (verbatim, still in force):
  - Demo accounts only — never capture or log in with a real account.
  - Credentials are passed to workers through the pipe, never on the
    command line.
  - DPAPI-encrypted credentials at rest.
  - Slave normalizes (EA-faithful).
- The app supports real accounts in production, so real servers stay
  selectable; "demo first" is honored by **ordering** (demo servers sorted
  above real) and **labeling**, not by blocking.

## Architecture

A **Broker Catalog** merges three sources into one broker→servers map,
deduped by server name. Pure-logic core (no Qt, no network) is separated
from the live fetcher and the GUI, so each is unit-testable in isolation.

```
manager/
  brokers/
    __init__.py
    catalog.py      Broker / BrokerServer dataclasses + BrokerCatalog
                   (merge sources, dedup, demo-first sort, query). Pure.
    default.py      Loads the shipped brokers_default.json snapshot.
    live.py         TradeVPS fetch + parse + cache read/write. Best-effort,
                   timeout-bounded. No Qt.
    learned.py      Record/retrieve previously-used servers from settings.
  data/
    brokers_default.json   Shipped TradeVPS snapshot (zero-network fallback).
  gui/
    server_picker.py   BrokerServerPicker widget (Broker combo + Server
                       combo + Refresh button). Reused by both forms.
  settings/
    store.py            (existing) — add a `learned_servers` list field.
```

## Data model

```python
@dataclass(frozen=True)
class BrokerServer:
    name: str                 # e.g. "ICMarketsSC-Demo"
    type: str                  # "demo" | "real" | "unknown"

@dataclass(frozen=True)
class Broker:
    name: str                 # e.g. "IC Markets" / "(Previously used)"
    servers: tuple[BrokerServer, ...]
    source: str                # "default" | "live" | "learned"  (for debug)
```

`BrokerCatalog`:
- `brokers: list[Broker]` — merged, deduped. `(Previously used)` first
  (if non-empty), then real brokers alphabetical by name.
- `broker_names() -> list[str]` — for the Broker combo.
- `servers_for(broker_name) -> list[BrokerServer]` — demo-first, then
  real, then unknown; within a group, alphabetical by name.
- `add_learned(server: str)` — append to the `(Previously used)` broker
  (dedup), in memory (persistence is the controller's job via `learned.py`).

Merging rule: brokers from different sources with the same normalized
name (case-insensitive, trimmed) are **one broker** whose server sets are
unioned. A server name appearing under multiple sources is a single entry.

## Sources

### 1. Shipped default (`brokers_default.json`)
A snapshot of the TradeVPS list committed to the repo, so first run works
with no network. Format identical to the TradeVPS response (top-level
`{"brokers":[…]}`) so the same parser serves both. Regenerated by a small
script that fetches TradeVPS and writes the file (run manually before
release; not part of CI).

### 2. Live cache (`brokers_cache.json`)
- `manager/brokers/live.py`:
  - `fetch_live(timeout=10.0) -> dict | None` — GET the TradeVPS URL;
    on ANY error (network, timeout, non-200, bad JSON) return `None`.
    No exceptions escape.
  - `load_cache(path) -> dict | None` — read cached JSON + its
    `fetched_at` timestamp; `None` if missing/corrupt.
  - `refresh_cache(path, timeout=10.0) -> dict | None` — fetch, write
    `{"fetched_at": <iso>, "brokers":[…]}`; return the parsed brokers or
    `None` (cache left untouched on failure).
- Cache path: the settings directory (same directory the settings store
  writes to), file `brokers_cache.json`. Cache considered fresh for 24h;
  older → re-refresh.
- The UI labels the live list as "community list" (crowd-sourced, not
  official) so the user knows its provenance.

### 3. Learned (`learned.py` + settings store)
- On a worker reaching **ready** with `account_info.server` populated, the
  controller calls `learned.record(server)` → appends (dedup) to a
  `learned_servers: list[str]` field in the settings store (DPAPI store is
  unchanged; this is non-secret public server names, plain JSON is fine).
- `learned.load() -> list[str]` returns them; the catalog surfaces them
  under the pseudo-broker `(Previously used)`.

## GUI — `BrokerServerPicker`

A reusable QWidget (`manager/gui/server_picker.py`) used by both
`main_window.py` (master form) and `slave_editor.py`:

```
Broker:  [ (Previously used) / broker names ▼ ]   [Refresh]
Server:  [ servers for selected broker ▼ ]
```

- `broker_combo`: editable `QComboBox`, type-to-filter. Items:
  `(Previously used)` (only if non-empty), then broker names alphabetical.
- `server_combo`: editable `QComboBox`. Selecting a broker repopulates it
  with `servers_for(broker)`, demo first. Each dropdown item's **display
  text** is `"<server> (demo|real)"` for scannability, but the raw server
  name is stored as the item's **user data** (`setItemData(name)`) so the
  returned value never includes the label suffix. The user can also type
  any server free-text and press Enter (no suffix).
- `Refresh` button → calls `refresh_cache` (best-effort) and repopulates;
  on failure, leaves the current list and emits a status/log warning.
- Public API: `server() -> str` (raw server name — the selected item's
  user data if a dropdown item is selected, else the typed free text, with
  any trailing ` (demo)`/` (real)` label stripped), `set_server(name)`,
  `set_broker(name)` (for editing existing accounts).
- No credentials, no broker login. Purely a name picker.

Wiring:
- `main_window.py`: replace `self.master_server = QLineEdit()` with the
  picker; `AccountSpec(..., server=self.master_picker.server(), ...)`.
- `slave_editor.py`: replace `self.server = QLineEdit()` with the picker;
  `spec()` uses `self._picker.server()`. When editing an existing slave,
  `set_server(...)` pre-fills.

## Data flow

1. **App start** → controller builds `BrokerCatalog` from default + cache (if
   fresh) + learned → passes broker names to the pickers. A background
   thread (or the existing `_UpdateWorker`-style QThread) fires
   `refresh_cache`; on success it signals the GUI to rebuild the catalog
   and repopulate open pickers.
2. **Configure** → user picks broker → server combo fills → user picks/types
   server → `picker.server()` → `AccountSpec.server` → worker
   `mt5.initialize(server=…)` unchanged.
3. **Learn** → worker ready status carries `account_info.server` →
   controller `learned.record(server)` → persisted → appears under
   `(Previously used)` next launch (and on a Refresh that rebuilds).

## Error handling

- Live fetch fails/timeout/parse error → `None`; catalog uses default +
  cache + learned; log a warning; no crash, no blocking.
- Cache missing/corrupt → ignored; default + learned used.
- No brokers at all (impossible — default ships in-repo) → picker still
  accepts free-text server entry; broker combo has a single `(manual)` row.
- A broker with zero servers → still listed; server combo empty + editable.
- Refresh while offline → leaves the current list, shows "community list
  unavailable" in the log, no modal dialog.

## Testing

- `test_catalog.py`: merge/dedup across sources, demo-first sort,
  `servers_for`, `(Previously used)` placement, normalized broker-name
  merge (case/trim). Pure-logic, no Qt, no network.
- `test_live.py`: parse a TradeVPS-shaped JSON fixture; cache write then
  read round-trip; timeout/non-200/bad-JSON all return `None` (mocked
  HTTP via `monkeypatch`); `fetched_at` freshness check.
- `test_learned.py`: record dedup + persistence (tmp settings file).
- `test_server_picker.py` (PySide6, importorskip): broker→server
  population, demo-first, free-text server entry, `server()`/`set_server`.
- `test_controller.py` (extend): a ready-status carrying
  `account_info.server` → `learned.record` called once with that server.
- Headless gate = no new failures; PySide6 tests skip cleanly when PySide6
  absent (existing pattern).

## Out of scope (YAGNI)

- No MetaQuotes internal-registry scraping (no public endpoint; fragile).
- No MetaApi integration (needs a paid auth token).
- No auto-discovery of server from the login number alone (not exposed by
  the Python API; would require driving the terminal UI — fragile).
- No per-account broker guessing from the login.
- No editing/curating the broker list from the GUI (learned covers the
  gap; the shipped default + live refresh cover the rest).

## Open data

The shipped `brokers_default.json` is a snapshot of the TradeVPS community
list. The user's own brokers don't need to be pre-added: any broker not in
the list is reachable by typing the server once (it then becomes learned).
